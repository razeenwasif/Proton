CAD

Parts, assemblies, drawings and boards, built K0–K13 and E0–E5 as docs/CAD.md planned them. What is left, and what waits on you.

  • The FormD T1's inside
    Waiting on you

    Where the board, the card, the spine and the power supply sit is not published (no model; the manual's spacings are pictures). Measure them, or say to assume NCASE's V2.5 where you can't.

  • The build's parts
    Waiting on you

    Your PCPartPicker list and the loop's pieces and tubes, so the library makes those first and the makers' STEP files can be fetched, each asked for.

  • A board for the case, first or after?
    Waiting on you

    Whether a custom board (a fan or light hub, a cable tidy) comes before the build is finished.

  • Curved panels?
    Waiting on you

    A spline in a profile is refused: extruded or turned it sweeps a surface the kernel does not have. Two exact swept surfaces would add it, if curved panels are wanted.

  • The two unchecked pinouts
    Waiting on you

    The 12V-2×6 connector's sense pins (S1–S4) and the USB-C Key-A front-panel header were written from memory and are marked so in the app: check them against the specifications.

  • Proton's files in other programs
    Waiting on you

    A STEP written by Proton has been read back by Proton only; KiCad is not on this Mac, so its libraries were read from test files.

  • Silkscreen text
    Later build

    Boards have outlines and references drawn, but no text of your own on the silkscreen.

  • More sheet metal
    Later build

    Flanges added on an existing sheet's edge, and holes carried into flat patterns; today a sheet is bent along one sketch.

  • Zone islands
    Later build

    Copper left unconnected inside a zone is not yet found and removed.

  • Hard corners for rounds and shells
    Later build

    Four or more rounds to a corner, rounds of two sizes meeting, shells of thick walls, and two surfaces that nearly touch are refused, naming where.

  • Smaller 3MF
    Later build

    3MF is stored, not compressed: about 60 bytes a point. A deflate of Proton's own would make it a fifth of that.

  • Free-form surfaces, simulation, CAM, an autorouter
    Later build

    Not built by choice: NURBS modelling is a kernel of its own size again; stress, thermal and flow simulation, toolpaths and autorouting are later builds if asked for.

Using Proton

How to get around Proton, one mode at a time. Proton is modal everywhere: vim keys drive the editors, and ␣ is the leader. Keys are written the Mac way.

Start hereThe windowProjectsCodexDataResearchExcelCircuitLogicCAD

Start here

  1. Open a project

    ⌘O opens a folder; so do ␣ f p and :cd folder. ␣ p n and ␣ p p move between open projects. Each mode keeps its own.

  2. Switch modes

    ⌃1–⌃7: Codex, Data, Research, Excel, Circuit, Logic and CAD. Bare digits stay vim counts.

  3. Use the leader

    In normal mode, press ␣ and wait: a key menu shows what comes next. ␣ f f finds files, ␣ f g searches text, ⌘K opens Telescope.

  4. Ask the agent

    Type in the dock on the right and press ↩ (⇧↩ for a new line). @selection, @dataframe or @sheet shows it what you mean. Its edits wait as a diff until you accept them.

  5. Change settings

    ⌘, opens Settings: models, text size, formatting. ⎋ or ⌘, closes it.

  6. Save

    Code saves with :w (:wq saves and closes, :q! throws changes away). Notebooks save when you switch, close or quit.

The window at a glance

Codex, with its usual panes open. The title bar runs down the right edge of every mode; what sits left of it changes with the mode.

Codex · the window
  1. 1Window controls

    Close, minimise, full screen. The title bar runs down the right edge, so the editor gets the whole height.

  2. 2Projects

    This mode's open projects, one tile each; a dot means unsaved work. + opens a folder (⌘O, ␣ f p).

  3. 3Mode rail

    Seven modes, ⌃1 to ⌃7. It scrolls when the window is short; the mode on screen is raised.

  4. 4Panel buttons

    Hide the sidebar, show the terminal (⌃`), hide the right panel, Settings (⌘,).

  5. 5File tree

    The project's files. ␣ e shows the current file here; ␣ f f finds one by name.

  6. 6Buffer bar

    The file's path, then undo, redo, split right (:vs), split down (:sp) and close the split.

  7. 7Editor

    Vim keys, always: :w saves. Marks in the gutter are git changes and the language server's problems.

  8. 8Terminal

    A real shell in the project folder, beside the editor. ⌃` shows or hides it.

  9. 9Agent head

    The thread's name, a new thread, past threads, and the panels: Tasks, Debug, Visualizer, Device, Git, Terminal.

  10. 10Conversation

    The agent's replies and the diffs it proposes, which wait for you to accept them.

  11. 11Composer

    ↩ sends, ⇧↩ adds a line. @selection, @dataframe or @sheet shows it what you mean.

Mode by mode

Codex · ⌃1

The code editor: vim keys, buffers as tabs, splits, language servers, a debugger, git, a terminal and the agent dock.

  • Save with :w. There is no ⌘S in the editor.
  • ⌘V pastes the clipboard; yanks and deletes also go to the clipboard.
  • gd, gr and K ask the language server; ␣ l … renames, finds code actions and formats; ␣ d … debugs.
  • Format on save is on, but C and C++ are left as written unless Format C and C++ too is on.
  • ⌃` shows the terminal; ␣ w … manages splits.
Data · ⌃2

Jupyter notebooks. Cells run in a kernel; dataframes show as tables beside them.

  • j k move between cells, i edits one, ⇧↩ runs it and goes back to normal mode.
  • o O add cells; dd, yy, p delete, copy and paste them.
  • The kernel is found in this order: PROTON_PYTHON, the project's .venv, the notebook's kernelspec, then a Python with ipykernel on PATH.
  • The Agent tab reads and runs your cells and proposes changes on them. Data keeps its own open project.
Research · ⌃3

Investigations run by Claude Code, Codex and Antigravity together, kept as plain files in research/<slug>/.

  • Run round proposes, reviews, ranks and evolves hypotheses; the Activity tab follows every call.
  • In the composer, /h Title: statement adds your own hypothesis and /p with a DOI or arXiv id adds a paper.
  • The Literature tab searches arXiv, Semantic Scholar and OpenAlex.
  • The Lab runs approved code in a sandbox and checks mathematics in Lean; setting it up asks you twice.
Excel · ⌃4

Spreadsheets, kept as .sheet folders of text; .xlsx, .csv and .tsv open and save as themselves.

  • h j k l move; typing starts a cell, ↩ or i edits it, ↩ and ⇥ commit and move.
  • v selects a range, V rows; y d p copy, cut and paste with formulas moved; dd and o take out and put in rows.
  • The format bar: bold, alignment, number formats, colours, sorting, filters, colour rules, charts, and → Data to send a range to a notebook.
  • :freeze, :sort, :filter, :width, :format, :chart. Edits wait for ⌘S; u undoes.
  • The agent on the right reads, writes and charts the workbook; @sheet sends what is selected.
Circuit · ⌃5

Digital logic after hneemann's Digital, kept as .circuit folders of text; Digital's .dig files open as projects of their own.

  • a places a part by name and ␣ the last one again; w starts a wire at the cursor and ends it; or drag from a pin with the mouse. h j k l move the cursor.
  • r turns, m mirrors, x deletes, ↩ edits a part's settings; y p copy and paste as text.
  • ⌘R runs it: click the inputs; s a clock edge, . a gate's delay, c the clock left running; the bolt quick-runs until a Break rises, ⎋ stops.
  • t opens the panel: test tables and their graph, truth tables and K-maps with synthesis, and state machines written as text. Export writes Verilog, VHDL or SVG.
  • The agent on the right reads, edits, tests and analyses circuits; @circuit sends the one on screen. Edits wait for ⌘S; u undoes.
Logic · ⌃6

A calculator after logic-calculator.com and a model finder after Logic for Fun, with proofs. .logic files are worksheets or theories in Proton's language, .l4f files Logic4Fun's, .proof files proofs; all are text.

  • The line at the cursor is answered as you type: a formula's truth table, whether it is a tautology, its normal forms and Karnaugh map; an argument's validity, with a countermodel or its Tableau; two formulas' equivalence. ⌘↩ asks it at once.
  • ⌘⇧↩ finds a theory's models, or checks a proof line by line with each mistake named. Count them all searches on; ⎋ stops a search. When there is no model, the fewest lines that cannot all hold are marked.
  • Proofs in natural deduction (Fitch), the sequent calculus and resolution; Find a proof writes one in the file's own system. Build in Circuit draws a formula's gates.
  • The symbol buttons type ¬ ∧ ∨ → ↔ ⊨; typed ASCII reads the same. Edits wait for ⌘S.
  • The agent on the right asks, solves, proves and writes with its logic tools; @logic sends the file, the line at the cursor and the last result.
CAD · ⌃7

Parts, assemblies, drawings, schematics and boards, each a text file (.part, .assembly, .drawing, .schematic, .board) built on Proton's own exact kernel. STEP, STL and DXF from other programs open read-only.

  • A part's steps are on the left, each with its mistake marked; the chosen step's settings on the right; the Text tab is the file itself.
  • In a sketch: l line, r rectangle, c circle, a arc, p point, s select; h v d x hold horizontal, vertical, a dimension or construction; f fits. The solver says how many freedoms are left.
  • Assemblies place parts by mates picked on two faces, check clearances and the FormD T1's limits, route hard and soft tube, and list the bill of materials.
  • Drawings project views with hidden edges, sections and dimensions; an assembly's blueprint prints on paper or white on blue, as PDF, SVG or DXF.
  • Boards: Track clicks from pad to pad, Via drops one; design rules are checked as you go, and Gerbers and drills writes a fab's files.
  • Edits wait for ⌘S. The agent on the right reads, writes, measures and checks with its CAD tools; @cad sends the file on screen.
